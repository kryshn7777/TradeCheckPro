# Packaging the immersive PWA for Meta Quest (Bubblewrap): owner notes for the free release

Run on the **owner's release machine**, not in CI: it touches the permanent signing key. This is the short, exact
version of RELEASE.md section 11 for the free Chapter I build. Everything in `dist-at3d/twa/` was generated by
`npm run build:at3d-release` from `tools/abyssal-tether-3d/release/release.config.json`.

## 0. What the build gives you

```
dist-at3d/web/            deploy this folder to the host (atomically, never file by file)
  index.html              landing page
  play/                   the game (manifest.webmanifest, sw.js, icons/, src/, vendor/, assets/)
  privacy/  support/      pages for the Dashboard (outside the service-worker scope on purpose)
  _headers                Cloudflare Pages / Netlify headers (translate for other hosts)
dist-at3d/twa/            never deploy
  twa-manifest.json       Bubblewrap config (tokens left where you must decide: __SHA256_COLON_HEX__)
  assetlinks.template.json, build-and-upload.sh, BUBBLEWRAP.md
dist-at3d/BUILD_REPORT.json   what was built, sizes, warnings
```

The APK is only a shell: it opens `https://<domain>/play/index.html` in a Trusted Web Activity in **immersive mode**.
The website is the product; web-only fixes need only a redeploy.

## 1. Before you build (owner actions; RELEASE.md sections 4-6)

1. Domain with HTTPS and a host with header control (Cloudflare Pages, Netlify, Vercel). GitHub Pages cannot serve
   `/.well-known/assetlinks.json` at the origin root, so it cannot be the store host.
2. Edit `tools/abyssal-tether-3d/release/release.config.json`: `owner.*` (studio, contact email, domain, postal
   address, effective date, host, log retention) and `bubblewrap.*` (package id `com.<studio>.abyssaltether`, Meta app
   id). The privacy / support pages and the TWA config are filled from it. Re-run the build.
3. Meta developer organization, Developer Distribution Agreement, the app created in the Dashboard (platform Meta
   Quest) so you have the numeric App ID. No financial account is needed for a free app with no add-ons.
4. Create the signing key ONCE, outside every repo and web folder; back it up in two offline places. Losing it means a
   new store listing:

```bash
KT=$(find ~/.bubblewrap/jdk -path '*/bin/keytool' | head -1)
mkdir -p ~/secure && chmod 700 ~/secure
"$KT" -genkeypair -v -keystore ~/secure/abyssal-tether.keystore -alias abyssaltether \
  -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=Abyssal Tether, O=<Studio>, C=<CC>"
"$KT" -list -v -keystore ~/secure/abyssal-tether.keystore -alias abyssaltether | grep SHA256
```

## 2. Build the web side and deploy it

```bash
npm run build:at3d-release                 # add -- --minify for smaller JS; -- --smoke runs the browser PWA test on the result
npm run test:at3d-release                  # optional: PWA install / offline / update test against dist-at3d/web/play
```

Deploy `dist-at3d/web/` atomically. The service worker rejects a half-finished deploy (players stay on the previous
build) but an atomic deploy avoids delaying updates. Then check:

- `https://<domain>/play/manifest.webmanifest` is served as `application/manifest+json`
- `https://<domain>/play/sw.js` has `Cache-Control: no-cache`
- `https://<domain>/.well-known/assetlinks.json` returns 200 with your package id and key fingerprint (below)

## 3. Package

```bash
npm i -g @meta-quest/bubblewrap-cli@1.24.1          # Meta's fork (the upstream package has no Horizon fields)
bubblewrap doctor                                   # offers to install JDK 17 + Android SDK: accept
mkdir -p ~/release/abyssal-tether-twa && cd ~/release/abyssal-tether-twa
cp <repo>/dist-at3d/twa/twa-manifest.json .
# put the keystore fingerprint (SHA256 colon-hex) into twa-manifest.json, replacing __SHA256_COLON_HEX__
bubblewrap fingerprint add <SHA256-colon-hex> --name=release   # writes ./assetlinks.json: publish it at /.well-known/assetlinks.json
export BUBBLEWRAP_KEYSTORE_PASSWORD='...' BUBBLEWRAP_KEY_PASSWORD='...'
bubblewrap update --appVersionName=1.0.0            # regenerates the Android project, bumps appVersionCode
bubblewrap build                                    # -> app-release-signed.apk
```

Settings that matter (already in the generated `twa-manifest.json`):

| Field | Value | Why |
|---|---|---|
| `horizonOSAppMode` | `immersive` | an immersive app set to `2D` shows a browser URL bar |
| `startUrl` / `fullScopeUrl` | `/play/index.html` / `/play/` | the manifest's `start_url` and `scope` are relative, so the same build works at any path |
| `enableMicrophone`, `enableXRScene` | `false` | Security.2: minimum permissions |
| `features.horizonBilling` | enabled in the template | for the later paid unlock. For the **free** release you can set `"horizonBilling": {"enabled": false}` and `"alphaDependencies": {"enabled": false}`; keep it enabled only if you want the final APK to be able to sell the unlock without a repackage (RELEASE.md Q18: `POST_NOTIFICATIONS` for billing) |
| `minSdkVersion` | 23 | raise to 29 if the uploader rejects it (RELEASE.md Q8) |
| launcher name | at most 12 characters | `Abyssal` |

Check the APK before it leaves the machine (`dist-at3d/twa/build-and-upload.sh build` does all of this):

```bash
BT=$(ls -d ~/.bubblewrap/android_sdk/build-tools/* | sort -V | tail -1)
"$BT/apksigner" verify --verbose --print-certs app-release-signed.apk          # v2 scheme, SHA-256 == keystore
"$BT/aapt" dump xmltree app-release-signed.apk AndroidManifest.xml | grep -A1 -E 'APP_MODE|OCULUS_APP_ID|category.VR'
"$BT/aapt" dump permissions app-release-signed.apk                             # justify each in the Dashboard
```

## 4. Upload and release

```bash
./ovr-platform-util upload-quest-build --app-id <APP_ID> --app-secret <APP_SECRET> \
  --apk app-release-signed.apk --channel ALPHA --age-group TEENS_AND_ADULTS \
  --notes "shell 1.0.0 (code N) / web 1.0.0+<hash from BUILD_REPORT.json>" --disable-progress-bar
```

Uploading never submits for review: finish the listing from `LISTING.md` (art, screenshots, text, comfort **Intense**,
age **Teens and Adults**, IARC, privacy URL, support URL), test on a Quest 3 (checklist in RELEASE.md section 12 and
`docs/abyssal-tether-3d/vrc-checklist.md`), then press **Submit for Review** in the Dashboard.

## 5. After launch

- The live app always runs whatever is deployed at `/play/`. Treat a deploy like a release: test the dist on a headset
  first (ALPHA channel pointing at `/beta/`, RELEASE.md section 12).
- `appVersionCode` must strictly increase across every upload on every channel.
- A new web build reaches players on their next launch (service worker); `AT3D.debug.platform()` shows the build id.
